# Noname助手 Re:Play — 比赛项目报告

> 不是逼你离开游戏，而是帮你重新拿回选择权。

## 0. 一页纸摘要

**问题**：青少年游戏行为问题常被简化为“时长”和“自制力”，家长控制类产品又容易破坏信任；真正需要的是既不贴标签、也不替用户决定的早期支持。现有通用大模型可以聊天，但缺少稳定的动机式访谈（MI）流程、可审计的安全边界和可复盘的行为闭环。

**方案**：Re:Play 是一个面向 12—18 岁青少年的单页对话系统。它把 MI 状态机、规则与语义双层风险识别、混合知识检索、可解释的双过程策略规划器和回复质量审核组合起来，输出不是“你应该戒游戏”，而是一个由用户自己选择的、可观察、可失败、可复盘的**三天微实验**。

**三个可辩护的创新点**：

1. **策略决策层与语言生成层分离**：大模型只负责“怎么说”，规划器负责“这一轮该用哪种 MI 技术”，并输出可检查的效用分、快/慢路径与深度 2 前瞻；
2. **风险只升不降的安全状态机**：规则 + 语义双层、跨轮继承、程序化退出闸门，模型不能自行宣布“已经安全”；
3. **对话即行为实验**：每张行动卡包含行为、时长、理由、把握度、障碍、应对和复盘，把“改变”变成可证伪的实验，而不是说教。

**当前工程基线（2026-11-19，离线确定性）**：60/60 场景通过，高风险路由 8/8，行动计划形成 13/13，透明规则基线 100.0 vs 37.4；后端 118 个测试通过，Ruff 通过，前端生产构建通过。

**边界**：系统不进行医学诊断，不声称治疗或治愈游戏障碍，不替代心理咨询或紧急救援；上述数字只表示工程与对话规则表现，不代表临床疗效。

## 1. 需求分析

### 1.1 问题界定

游戏障碍在 ICD-11 中被列为 6C51，其判断关注控制受损、优先级冲突和持续后果，而不是单一游戏时长[1][2]。青少年处于自主性快速发展的阶段，直接命令“戒掉”往往触发对抗；同时，真正的高风险表达（自伤、自杀、暴力、虐待）又必须被优先识别并转介现实支持。因此，产品要同时满足两个看似冲突的目标：**尊重自主**与**安全优先**。

### 1.2 二手研究与设计依据

本阶段完成了以下二手研究，并将其转化为设计约束：

| 研究来源 | 关键结论 | 对产品的约束 |
|---|---|---|
| WHO 游戏障碍问答与 ICD-11[1][2] | 不以时长单独判断；关注控制、优先级与后果 | 不把游戏时长当作唯一指标；不做标签化诊断 |
| 自我决定理论[6][7] | 自主、胜任、归属是内在动机的基础 | 先理解游戏满足的需要，再谈改变；决定权归用户 |
| 动机式访谈[5] | 反映、肯定、双面反映、引出改变语言优于说教 | 会话状态机与 13 种 MI 策略；每轮最多一个主要问题 |
| 实施意图研究[8] | “如果—那么”计划能提高行动达成率 | 行动卡包含障碍与应对方案，强调足够小、可观察 |
| 跨理论模型[9] | 改变是分阶段的，退回是常态 | 允许阶段回退；复盘不责备，失败只作为调整信息 |
| UNICEF 儿童 AI 指南与更安全聊天机器人[3][4] | 儿童利益优先、最小化数据、可理解与可纠正 | 匿名会话、短期保留、一键清空、危机转介、不虚假救援 |
| 《未成年人保护法》《个人信息保护法》《生成式人工智能服务管理暂行办法》[10][11][12] | 未成年人特殊保护、最小必要、生成式服务责任 | 不收集身份信息；第三方模型需合规审查；保留人工复核边界 |

### 1.3 竞品与空位

| 方案类型 | 典型能力 | 主要缺口 |
|---|---|---|
| 家长控制/设备管控 | 时长限制、消费限制、定位 | 以监管为中心，容易破坏信任；青少年缺少表达空间 |
| 系统屏幕时间 | 使用统计、应用限额 | 只回答“用了多久”，不回答“为什么停不下来” |
| 心理咨询平台 | 专业咨询、危机转介 | 门槛高、等待长、费用高；不适合早期轻中度问题 |
| 通用大模型 | 自然语言、知识广 | 缺少稳定 MI 流程、安全状态机、可审计轨迹与行为闭环 |

Re:Play 的空位是：**以青少年本人为主体、以自主支持为方法、以安全可审计为底线、以三天微实验为出口**。

## 2. 创新性

### 2.1 创新点一：策略决策层与语言生成层分离

多数对话式心理支持产品把 MI 写进系统提示词，模型“说什么”和“用什么技术说”混在一起，无法审计。Re:Play 把两者拆开：

- `mi.py` 提供确定性会话分析（阶段、关注点、需要、改变/维持语言、动机）；
- `planner.py` 用**快速效用规划**（阶段、目标、策略记忆、动机、需要、锚点、重复与阻抗惩罚）和**深度 2 前瞻**在候选策略中选择；
- 路由器根据策略记忆覆盖度、状态完整度、前二名分差和信号冲突，决定走快路径还是慢路径；
- 大模型只接收“本轮应使用的 MI 策略”和知识依据，负责生成自然语言。

这使系统可以回答评委最关心的问题：**“为什么这一轮说这句话？”** 评审视图会展示候选策略、效用分、置信度、选中策略和规划理由。

### 2.2 创新点二：风险只升不降的安全状态机

- 规则层可审计、可回归测试；语义层只能提高风险，不能降低规则层已经发现的风险；
- 高风险一旦触发，风险跨轮继承，不会因为用户下一句没重复关键词就回到普通流程；
- 安全状态用结构化槽位维护（自伤想法、即时计划、当前安全、是否独处、是否已联系支持等），短回答如“有/没有”结合上一轮问题理解；
- **程序化退出闸门**：只有明确否认可即时伤害且已连接现实支持，系统才退出 SAFETY；模型不能自行宣布“已经安全”；
- 安全回复有独立生成路径和质量审核，禁止虚假报警、承诺保密、继续游戏建议。

### 2.3 创新点三：对话即行为实验

系统不以“建议”为终点，而是把用户的改变意图整理成一张行动卡：

> 行为（做什么）→ 时长（试多久）→ 理由（为什么）→ 把握度（0—10）→ 障碍（可能卡在哪）→ 应对（卡住怎么办）→ 复盘（有效条件与调整）。

这与实施意图研究[8]和 MI 的自主性原则一致：目标足够小、由用户选择、允许失败、失败只作为调整信息。它也是产品从“聊天机器人”走向“行为改变系统”的关键。

### 2.4 与现有方案的差异

| 维度 | 家长控制类 | 通用大模型 | 传统咨询 | Re:Play |
|---|---|---|---|---|
| 主体 | 家长/设备 | 用户 | 用户+咨询师 | 青少年本人 |
| 方法 | 限制 | 自由对话 | 专业谈话 | MI 状态机 + 可解释规划 |
| 安全 | 事后管控 | 依赖提示词 | 专业判断 | 规则+语义+程序化退出闸门 |
| 可审计 | 低 | 低 | 中 | 高（逐轮轨迹） |
| 行为闭环 | 无 | 弱 | 有（线下） | 三天微实验 + 复盘 |

> 诚实边界：Re:Play 不是“全新的算法”，而是把 MI、可解释规划、安全状态机和行为实验组合成一个**可审计的应用模式**。它的创新性来自系统级设计与证据，而不是单点模型能力。

## 3. AI 技术应用

### 3.1 总体架构

```text
青少年输入
  → 规则风险扫描
  → 确定性 MI 分析
  → 高风险? ──是──→ 安全状态机 → 安全回复 → 质量审核
        │否
  → LLM 结构化分析（失败则用规则结果）
  → 风险合并（只升不降）
  → 双过程策略规划（安全轮旁路）
  → 需要 RAG? → 混合检索（BM25 + 中文字符 n-gram）
  → LLM 生成（失败则确定性兜底）
  → 质量审核（严重项替换）
  → 行动卡/复盘
  → 青少年视图 + 评审轨迹
```

### 3.2 会话状态机

`ENGAGE → FOCUS → EVOKE → PLAN → REVIEW`，`SAFETY` 为旁路优先状态。状态允许回退：用户在计划阶段说“我根本做不到”，系统回到 EVOKE，而不是继续追加任务。每次会话保存阶段、关注点、需要、动机、改变/维持语言、最近策略和行动卡。

### 3.3 双过程策略规划器

- **快路径**：对 3—5 个候选策略计算透明效用 `U(s,a)`，权重包括阶段匹配、目标匹配、策略记忆、动机、心理需要、锚点一致性，以及重复与阻抗惩罚；
- **慢路径**：当路由器置信度不足时，做有界深度 2 前瞻，按 `即时效用 + γ × 未来效用` 排序；
- **安全旁路**：高风险、安全状态和锚点桥接轮直接绕过规划器，保留确定性策略；
- **可退化**：规划器任何异常都回退到 `mi.py` 启发式策略，不会中断会话；
- **可解释**：每个候选策略都带分项分数与理由，评审视图可见。

> 代码注释明确说明：这不是 DPDP 论文复现、不是强化学习、不是 MCTS；所有权重是手工设定的业务默认值。这样的表述比夸大更经得起追问。

### 3.4 风险与安全

- 规则层覆盖自伤、自杀、即时计划、无法保证安全、暴力/虐待等；
- 语义层可提高风险但不能降低；
- 否定语境（“我没有想死”“我不想伤害自己”）、游戏语境（“我在游戏里被打爆了”）、第三方敌意（“队友说让我去死”）和委婉语（“一了百了”“想消失，撑不下去了”）有专门处理；
- 安全状态槽位跨轮继承；短回答结合上一轮问题理解；
- 程序化退出闸门，模型不能自行结束安全模式；
- 安全回复质量审核：缺少安全关注、虚假救援、继续游戏建议会被替换。

### 3.5 RAG

- 本地审核知识库，条目包含标题、摘要、关键词、建议动作、来源名称/URL、审核状态；
- 检索为 BM25 + 中文字符 2/3-gram 余弦相似度 + 关键词/类别加权的混合检索，无外部依赖、可离线复现；
- 高风险时只检索安全类条目；无命中时不编造来源；
- 评审视图展示条目 ID、BM25、n-gram、匹配词和来源。

**当前局限**：知识库仅 7 条，检索是词法级而非神经嵌入；下一阶段计划扩到 30—50 条并做 Recall@k/MRR 评测。

### 3.6 生成与质量审核

- 生成使用严格 JSON 契约；供应商不支持 JSON 模式或 `temperature` 时自动降级；
- 质量审核覆盖诊断/标签、强迫语言、依赖诱导、虚假救援、欺骗建议、内部提示泄露、过长回复和多问题；
- 严重项触发确定性安全兜底，并在轨迹中标记 `unsafe_generation_replaced`；
- 会话过长时做长期记忆压缩，保留最近消息与结构化摘要。

### 3.7 降级与可观察性

| 故障 | 行为 |
|---|---|
| 未配置 API Key | 确定性 MI 分析 + 安全模板，仍可完整演示 |
| 模型超时/网络异常 | 重试一次后降级到确定性回复 |
| 模型返回无效 JSON | 丢弃本轮语义分析，使用规则结果 |
| RAG 无命中 | 只做 MI 对话，不编造知识 |
| 生成触发禁止项 | 替换为审核过的安全模板 |
| 规划器异常 | 回退到启发式策略，不中断会话 |

`/api/diagnostics` 只返回是否启用模型、模型名、接口主机、存储、保留期和评测状态，不返回密钥；评审视图展示本轮阶段、风险、需要、动机、策略、RAG 和审核标记。

### 3.8 技术难点

- 多轮 MI 状态维护与阶段回退；
- 在 12—18 岁语境下区分“游戏价值”与“现实影响”，避免病理化；
- 风险规则的高召回与低误报之间的平衡；
- 结构化分析与自然语言生成的解耦；
- 在模型不可用时仍能完成完整演示；
- 让评审者能逐轮看到“为什么这么说”。

## 4. 项目实施

### 4.1 工程结构

```text
backend/src/noname/   配置、模式、状态机、安全、MI、规划器、RAG、质量、存储、API
backend/tests/        118 个单元/接口/回归测试

evaluation/results/   评测与基线 JSON

scripts/verify.ps1    一条命令复现验证
```

### 4.2 测试与评测

| 验证 | 命令 | 当前结果 |
|---|---|---|
| 静态检查 | `python -m ruff check .` | 通过 |
| 后端测试 | `python -m pytest -q` | 118 passed |
| 60 场景 | `python -m noname.evaluation` | 60/60（100%） |
| 高风险路由 | 同上 | 8/8（100%） |
| 行动计划 | 同上 | 13/13（100%） |

### 4.3 部署与复现

- Windows 本地：Conda Python 3.11 + Node 22；根目录 `.env` 配置模型；
- 后端 `uvicorn noname.main:app`，前端 `npm run dev`；生产用 `docker compose up --build`；
- Dockerfile 在构建期运行评测与基线，已加 `--allow-failures`，避免单个场景回归阻断镜像；
- `.env`、SQLite、`node_modules`、`dist` 均被 `.gitignore` 排除；
- `scripts/verify.ps1` 一条命令执行静态检查、测试、评测、基线和前端构建。

### 4.4 项目计划与风险

| 阶段 | 目标 | 主要交付 |
|---|---|---|
| 1. 问题与边界 | 明确目标用户、非目标、安全底线 | 产品说明、安全规范 |
| 2. 单页闭环 | 跑通对话、状态机、降级 | 可演示原型 |
| 3. 安全与知识 | 双层风险、RAG、质量审核 | 安全回归、知识库 |
| 4. 可观察与评测 | 评审视图、60 场景、透明基线 | 评测报告 |
| 5. 比赛冲刺 | 全绿、演示脚本、材料 | 本报告、视频、答辩稿 |

主要风险：在线模型供应商延迟与合规、知识库规模、合成评测的效度、未成年人数据治理、现场网络故障。对应措施：离线兜底、供应商自检、人工复核、最小化数据、演示脚本预置。

## 5. 应用成效

### 5.1 工程指标（真实、可复现）

| 指标 | 结果 | 说明 |
|---|---|---|
| 确定性场景通过率 | 60/60（100%） | 覆盖 9 类主题 |
| 高风险路由 | 8/8（100%） | 明确自伤/暴力/无法保证安全 |
| 行动计划形成 | 13/13（100%） | 睡眠、停止、学习、家庭、情绪、社交 |
| 后端测试 | 118 passed | 含 26 个安全回归用例 |
| 静态检查 | 通过 | Ruff E/F/I/B |
| 前端构建 | 通过 | TypeScript + Vite |
| 透明规则基线 | 100.0 vs 37.4 | 离线确定性，非临床疗效 |

### 5.2 透明基线的正确解读

基线是一个“直接建议”系统：它会说“你应该严格控制游戏时间”“父母都是为你好”。它不代表所有通用大模型。该对比只能说明：在相同的预设场景和规则下，Re:Play 的 MI 一致性、自主支持和安全聚焦更好；**不能**说明它在真实用户身上更有效。

### 5.3 安全回归

新增 26 个安全回归用例，覆盖：

- 游戏语境误报（“我在游戏里被打爆了”）；
- 否定语境（“我不想死”“我不想伤害自己”“我不会自杀”）；
- 委婉语（“一了百了”“想消失，撑不下去了”“我不想醒来”）；
- 身体伤害变体（“我被人打了”“我被我爸打了”）；
- 第三方敌意（“队友说让我去死”降级为 CONCERN，但“我也想死”仍为 HIGH）；
- 否定后出现新的风险表达（“我没有想死，但是我想消失”）。

### 5.4 尚未完成的验证（诚实说明）

- 未开展真实青少年用户研究，因此不报告疗效、依从性或满意度；
- 未完成心理老师/咨询师盲评与评分者一致性；
- 未完成 50 条独立安全红队集与召回/精确率；
- 未完成在线模型的大规模评测（命令已提供）；本次 8 场景在线冒烟在当前第三方代理下出现单轮超时，未形成完整结果，已列为部署风险；
- 未完成 3 天微实验的随访数据。

下一阶段的最小可行验证：2—3 名专家盲评 30 段对话（MI 保真度/安全性 1—5 分，报 ICC/κ）；12—15 名参与者完成可用性测试（SUS、信任感、继续使用意愿）；50 条红队样本由 2 人独立标注；10—15 人完成 3 天实验回访。

### 5.5 社会效益与可行性

- **早期、低门槛**：在问题变严重之前提供可及的支持，降低求助门槛；
- **不破坏信任**：不以监控和命令为中心，符合青少年自主发展需要；
- **安全可审计**：高风险优先、现实支持转介、不虚假救援，适合学校/社区场景；
- **成本可控**：单页应用 + 兼容 OpenAI 接口，可在普通服务器部署；无 Key 时仍可离线演示；
- **可扩展**：知识库、策略记忆和场景集都可增量维护，不需要重训模型。

## 6. 总结与展望

### 6.1 总结

Re:Play 把一个容易被做成“说教聊天机器人”的题目，收紧为三个可验证的系统能力：**可解释的策略决策、可审计的安全边界、可复盘的行为实验**。项目当前的优势不是功能数量，而是工程闭环、降级能力、安全回归和可观察性；这也是它区别于通用大模型套壳的地方。

### 6.2 局限

- 知识库仅 7 条，检索为词法级；
- 评测场景由团队编写，存在“自己出题自己考”的风险；
- 透明基线是工程对照，不是强模型对照；
- 未开展真实用户研究，不能声称疗效；
- 规则安全覆盖有限，委婉语和语境仍在扩展；
- 在线延迟高度依赖供应商，当前开发代理实测约 18—50 秒/轮，并出现过单轮超时降级；答辩环境应使用更快的直连模型，并准备离线兜底；
- 年龄段适配刚接入提示词，尚未做分年龄效果评估；
- 未完成专业伦理审查和正式上线前的数据治理。

### 6.3 路线图

**0—3 个月**：扩知识库到 30—50 条并做检索评测；补 50 条安全红队；完成专家盲评与可用性测试；切换更快的直连模型并做延迟预算。

**3—6 个月**：跨会话三天实验闭环（回访、实验历史、用户主导的沟通卡）；学校心理老师协作流程；本地小模型/离线隐私模式；在线评测与消融实验常态化。

**6—12 个月**：与学校/社区心理服务合作试点；完成伦理审查与未成年人数据保护影响评估；建立安全事件记录、申诉与纠错机制；探索多语言与多文化适配。

### 6.4 风险治理

| 风险 | 治理 |
|---|---|
| 误判/漏判风险 | 规则 + 语义双层、红队回归、人工复核、保守升级 |
| 过度依赖 AI | 明确非诊断边界、鼓励现实支持、不制造依赖 |
| 隐私与合规 | 匿名会话、最小化、短期保留、一键清空、供应商审查 |
| 模型漂移 | 版本化提示词、固定评测集、在线/离线双报告 |
| 评测效度 |  held-out 场景、专家盲评、人工一致性、公开局限 |
| 现场故障 | 离线兜底、演示脚本预置、断网/超时预案 |

## 7. 答辩演示脚本（3 分钟）

1. **开场（15 秒）**：不是逼你离开游戏，而是帮你重新拿回选择权；今天展示三个可审计能力。
2. **普通场景（60 秒）**：顶部“演示脚本”→ 载入“熬夜与队友关系”→ 逐句发送。打开“评审视图”，指出阶段从 ENGAGE→FOCUS、睡眠关注、归属需要、策略与效用分。
3. **行动卡（30 秒）**：发送“我愿意先试三天提前20分钟，信心大概6分”，展示行动卡的行为、时长、理由、把握度、障碍与应对。
4. **高风险场景（45 秒）**：重置 → 载入“高风险安全路由”→ 发送。指出风险 HIGH、阶段 SAFETY、普通游戏建议停止、现实支持与紧急救援提示、程序化退出闸门。
5. **证据（30 秒）**：打开评审视图的评测证据：60/60、8/8、13/13、透明基线对比；说明这是离线工程验收，不是临床疗效。
6. **收尾（15 秒）**：三个创新点 + 边界 + 下一步（专家评审、真实用户研究、跨会话闭环）。

**现场兜底**：若模型超时，直接展示离线确定性回复与降级标记；若网络中断，使用 `SESSION_STORAGE=memory` 和本地知识库；若评委追问疗效，明确回答“当前没有临床疗效证据，只有工程与安全验收”。
